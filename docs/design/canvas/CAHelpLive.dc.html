Live updates (WebSocket) NEW

One live connection per open tab. Things appear the moment they happen — not after the next refresh. If the connection drops, the app quietly goes back to refreshing every minute.
WhereWhat becomes liveToday
HelpdeskNew tickets in the queue, replies, “is writing…”, status changes, assignmentsNow: refresh on open
Notification bellEvery module: leave approved, expense paid, asset handed over, kudos, announcementNow: every 1 min
Sidebar badgesCounts like “3 to approve”, “2 tickets” change at onceNow: every 1 min
Home & attendanceWho is in / away today, check-insNow: every 1 min
Announcements & kudosReactions and read counts tick up liveNow: on refresh
Super AdminMaintenance mode switch reaches every open tab at onceNow: polling

How it works (simple)

Kiran replies
saves in the API
API sends an event
“ticket 231 has a reply”
Amit’s open tab
shows it at once
• Socket.IO inside the NestJS API, signed in with the same login token.
• Each person joins only their own “rooms”: me, my company, and my team queues — so nobody gets events they may not see.
• Events say “something changed”; the page then loads the data through the normal API (same permission checks).
• One API server needs nothing extra. With 2+ servers we add Redis (already on the plan).
