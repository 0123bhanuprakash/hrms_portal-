Effect on speed — your question
0 ms

API response time

Animations run only in the browser. The server does the same work and sends the same data. The only new data is today’s celebrations and the kudos list — both come from endpoints we already have.

≈ 10 KB

Extra download

All effects are CSS (≈ 5 KB compressed). New chart styles are small SVG widgets (≈ 5 KB). No animation library and no 3D engine needed.

± 0 s

Page load time

Content shows as soon as data arrives; animations play on top and never block clicks. First-load numbers finish within 0.6 s.

< 2%

CPU while open

Only transform and opacity are animated (graphics card, no re-layout). Loops (carousel, kudos, check-in pulse) pause when off-screen or the tab is hidden.

The real cost to watch: profile photos

  • Celebrations, kudos and presence show many photos at once
  • We’ll serve small thumbnails (64 px, ≈ 4 KB) instead of full uploads
  • Photos load lazily and are cached; initials show until they arrive

How we’ll keep it honest

  • Measure home load before and after (Lighthouse + our perf scripts)
  • Budget: no more than +50 ms to first content, +15 KB download
  • “Reduce motion” in Preferences turns every animation off
  • Phones get lighter motion (no pointer effects)
